# Grant Manager Questions

## Purpose

This document lists questions to ask the grant manager before finalizing the application, budget, scope, and Phase I/Phase II plan.

The goal is to confirm fit, allowable costs, documentation expectations, and whether Phase I can use synthetic or de-identified data while deferring production security work to Phase II.

## Program Fit

1. Does a patient-controlled interoffice medical record request and consent platform fit this funding opportunity?
2. Should the project be framed primarily as health information exchange, patient-mediated interoperability, digital healthcare safety, care coordination, or biomedical informatics?
3. Is this a better fit for SBIR, STTR, AHRQ digital healthcare research, NIH/NLM, NIH/NIBIB, or another HHS pathway?
4. Does the program prefer research prototypes, commercialization-ready products, clinical pilots, or implementation studies?
5. Are software-only health IT projects eligible under this mechanism?

## Phase I Scope

1. Can Phase I focus on feasibility, prototype development, and workflow validation?
2. Can the Phase I prototype use synthetic or de-identified records instead of real PHI?
3. Is a third-party penetration test required in Phase I, or can it be deferred to Phase II before real PHI pilots?
4. How much HIPAA/privacy legal review is expected at Phase I?
5. Are provider and patient usability interviews allowable in Phase I?
6. Are pilot office workflow observations allowable if no real PHI is collected?
7. Should Phase I include a formal human subjects determination, IRB review, or exemption request if the work includes interviews?

## Budget

1. Is founder/PI salary allowable at approximately $80,000 for Phase I?
2. Should the founder/PI salary be listed as salary, consultant cost, or another category based on company structure?
3. Are fringe, payroll taxes, and payroll processing costs allowable?
4. Is a $130,000 lead developer budget reasonable for the technical scope?
5. Can HIPAA legal review be included as a project-specific compliance cost?
6. Can security architecture review be included in Phase I?
7. Can grant accounting, payroll, insurance, and administrative support be included?
8. Are cloud hosting, database, logging, monitoring, and development tools allowable?
9. Are participant incentives or site visit costs allowable for user discovery?
10. How should indirect costs or overhead be calculated for a small business without a negotiated indirect rate?

## Personnel And Eligibility

1. Does the PI need to be employed more than 50 percent by the small business at time of award?
2. Can the lead developer be a contractor, or should the person be an employee?
3. Are consultants acceptable for HIPAA legal, security, clinical workflow, and interoperability advising?
4. Are there limits on subcontractor or consultant costs?
5. Are letters of support from pilot providers recommended or required?

## Compliance And Data

1. What privacy and security documentation should be included in the application?
2. Should the application include a data management and sharing plan?
3. If only synthetic or de-identified data is used, what HIPAA documentation is expected?
4. If later pilot work handles PHI in Phase II, what should be promised in the Phase I application?
5. Should BAAs, consent forms, or patient authorization drafts be included as attachments?

## Technical Direction

1. Is it acceptable to describe ClearPath's internal hub language as a canonical JSON package?
2. Should the application explicitly connect the JSON package to FHIR, HL7, C-CDA, PDF, CSV, and reviewed-import translators?
3. Should direct EHR integration be deferred to Phase II?
4. Is a reviewed-import workflow acceptable as a safer Phase I alternative to direct EHR writes?
5. Should the application identify initial target systems or keep the focus vendor-neutral?

## Phase II Readiness

1. What evidence will make the project competitive for Phase II?
2. Does Phase II require real-world pilot data from Phase I, or is stakeholder validation enough?
3. Should the Phase I application include a preliminary Phase II security and compliance budget?
4. Should the application include commercialization milestones?
5. What level of customer discovery or letters of intent would strengthen the application?

## Most Important Question

Ask this clearly:

> Can Phase I use synthetic or de-identified records and include a HIPAA workflow consult plus security architecture review, with full penetration testing and production HIPAA implementation budgeted for Phase II before handling real PHI?
